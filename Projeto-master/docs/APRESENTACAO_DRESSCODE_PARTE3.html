8. Conexão: MVC + Repository + Padrões GoF

Exemplo Prático: Busca de Produtos

1️⃣ Controller (MVC)

// ProductController.php class ProductController { private $productRepository; public function __construct() { // Usa Singleton para conexão $db = DatabaseConnection::getInstance(); // Injeta no Repository $this->productRepository = new ProductRepository($db); } public function search() { $filters = $this->processFilters(); // Usa Strategy + Decorator $strategy = new BuscarProdutosStrategy( $this->productRepository, $filters ); $produtos = $strategy->search(); // Passa para View include 'views/products/search.php'; } }

2️⃣ Repository Pattern

// ProductRepository.php class ProductRepository { private $pdo; public function __construct(PDO $pdo) { $this->pdo = $pdo; // Recebe Singleton } public function executarBusca($search): array { // Executa SQL composto pelos Decorators $sql = $search->getSQL(); $params = $search->getParams(); $stmt = $this->pdo->prepare($sql); $stmt->execute($params); return $stmt->fetchAll(PDO::FETCH_ASSOC); } }

3️⃣ Strategy + Decorator

// BuscarProdutosStrategy.php class BuscarProdutosStrategy implements SearchStrategy { public function search(): array { $search = new ProdutoSearchBase(); // Aplica Decorators dinamicamente if (isset($this->filters['categoria'])) { $search = new FiltroCategoriaDecorator($search, ...); } return $this->repo->executarBusca($search); } }

4️⃣ Factory Method

// Após buscar do banco, cria objetos tipados $produtos = $repository->search($filters); foreach ($produtos as $produtoData) { $produto = ProductFactory::createFromDatabase($produtoData); // Agora $produto tem métodos específicos do tipo }

5️⃣ Observer

// Quando novo produto é adicionado $publisher = new ProductPublisher(); $publisher->attach(new NotificationObserver()); $publisher->notify('new_product', [ 'product_id' => $produto->id, 'product_name' => $produto->nome ]); // NotificationObserver cria notificações automaticamente

9. Benefícios da Arquitetura

🎯 Separação de Responsabilidades

Camada Responsabilidade Não faz
Controller Coordena fluxo Não acessa banco diretamente
Repository Acessa dados Não renderiza HTML
Model Regras de negócio Não conhece HTTP
View Apresentação Não acessa banco

✅ Vantagens Obtidas

Manutenibilidade

  • Código organizado e modular
  • Fácil localização de bugs
  • Mudanças isoladas não afetam todo o sistema
  • Documentação clara da arquitetura

Escalabilidade

  • Novos recursos podem ser adicionados facilmente
  • Padrões permitem extensão sem modificação
  • Sistema preparado para crescimento
  • Performance otimizada (Singleton, SQL eficiente)

Testabilidade

  • Cada componente pode ser testado isoladamente
  • Injeção de dependência facilita mocks
  • Repositórios podem usar banco de teste
  • Padrões facilitam testes unitários

Reutilização

  • Repositórios reutilizáveis em diferentes controllers
  • Decorators podem ser combinados de várias formas
  • Observers podem ser adicionados a múltiplos subjects
  • Factory centraliza criação de objetos

Performance

  • Singleton evita múltiplas conexões
  • Decorators aplicam filtros no SQL (não em memória)
  • Queries otimizadas nos repositórios
  • Cache pode ser implementado facilmente
