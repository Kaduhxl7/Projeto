1. Visão Geral do Projeto

O que é o DressCode?

O DressCode é um marketplace online especializado em brechós, conectando vendedores de roupas usadas e vintage com compradores interessados em moda sustentável e acessível.

Objetivos do Sistema

  • Facilitar a compra e venda de roupas de segunda mão
  • Promover sustentabilidade e economia circular
  • Conectar brechós físicos com clientes online
  • Oferecer sistema de busca avançado e personalizado
  • Gerenciar pagamentos e notificações

Tecnologias Utilizadas

Categoria Tecnologia
Backend PHP 7.4+
Banco de Dados MySQL 8.0
Frontend HTML5, CSS3, JavaScript
Arquitetura MVC + Repository Pattern
Padrões de Projeto Singleton, Factory, Observer, Strategy, Decorator
💡 Diferencial: O projeto implementa boas práticas de engenharia de software, utilizando padrões de projeto consolidados (GoF) para garantir código limpo, manutenível e escalável.

2. Arquitetura MVC

O que é MVC?

MVC (Model-View-Controller) é um padrão arquitetural que separa a aplicação em três componentes principais, promovendo a separação de responsabilidades e facilitando a manutenção.

Fluxo MVC no DressCode

┌─────────────┐
│   USUÁRIO   │
└──────┬──────┘
       │ Requisição HTTP
       ▼
┌─────────────────────────────────────┐
│         CONTROLLER                  │
│  (ProductController.php)            │
│  - Recebe requisição                │
│  - Processa lógica de negócio       │
│  - Chama Model/Repository           │
└──────┬──────────────────────────────┘
       │
       ▼

│  (Product.php, ProductRepository)   │

│  - Aplica regras de negócio         │
│  - Retorna dados                    │
└──────┬──────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│            VIEW                     │
│  (products/category.php)            │
│  - Renderiza HTML                   │
│  - Exibe dados ao usuário           │
└─────────────────────────────────────┘

Camadas no DressCode

📁 Model (app/models/)

Representa os dados e a lógica de negócio. Exemplos: Product.php, User.php, Brecho.php. Responsável por interagir com o banco de dados e aplicar validações.

🎮 Controller (app/controllers/)

Gerencia o fluxo da aplicação, recebe requisições do usuário e coordena Model e View. Exemplos: ProductController.php, AuthController.php.

👁️ View (app/views/)

Camada de apresentação, responsável por renderizar HTML e exibir dados ao usuário. Exemplos: products/category.php, dashboard.php.

3. Repository Pattern

Conceito

O Repository Pattern é um padrão que abstrai a camada de acesso a dados, criando uma interface entre a lógica de negócio e a fonte de dados. Ele centraliza as operações de banco de dados em classes específicas.

Por que usar Repository?

  • Separação de Responsabilidades: Isola a lógica de acesso a dados
  • Testabilidade: Facilita a criação de testes unitários
  • Manutenibilidade: Mudanças no banco não afetam controllers
  • Reutilização: Queries complexas podem ser reutilizadas
  • Abstração: Controllers não precisam conhecer SQL

Implementação no DressCode

// app/repositories/ProductRepository.php class ProductRepository { private $pdo; public function __construct(PDO $pdo) { $this->pdo = $pdo; } public function findById($id) { $stmt = $this->pdo->prepare("SELECT * FROM produtos WHERE id = :id"); $stmt->execute([':id' => $id]); return $stmt->fetch(PDO::FETCH_ASSOC); } public function search($filters) { // Lógica complexa de busca } }

Repositórios Implementados

Repository Responsabilidade
ProductRepository Gerencia produtos, buscas, favoritos
CategoryRepository Gerencia categorias de produtos
TermoRepository Gerencia termos de aceite
✅ Benefício: O controller não precisa saber SQL, apenas chama métodos do repository como findById() ou search().

4. Padrões GoF - Singleton

🔧 Singleton Pattern

Categoria: Criacional

Objetivo: Garantir que uma classe tenha apenas uma instância e fornecer um ponto global de acesso a ela.

Onde foi aplicado?

Arquivo: app/config/DatabaseConnection.php
Uso: Conexão única com o banco de dados MySQL

Por que usar Singleton para conexão de banco?

  • Performance: Evita criar múltiplas conexões desnecessárias
  • Recursos: Economiza memória e conexões do banco
  • Consistência: Todas as operações usam a mesma configuração
  • Controle: Ponto único para gerenciar a conexão

Implementação

class DatabaseConnection { private static ?PDO $instance = null; // Construtor privado - impede new DatabaseConnection() private function __construct() {} // Impede clonagem private function __clone() {} // Método público para obter a instância public static function getInstance(): PDO { if (self::$instance === null) { self::initializeConnection(); } return self::$instance; } private static function initializeConnection(): void { self::$instance = new PDO( "mysql:host=localhost;dbname=dresscode", "root", "" ); } }

Como é usado no projeto?

// Em qualquer lugar do código $db = DatabaseConnection::getInstance(); $repository = new ProductRepository($db);
✅ Resultado: Apenas uma conexão PDO é criada durante toda a execução, melhorando performance e reduzindo uso de recursos.

4. Padrões GoF - Factory Method

🏭 Factory Method Pattern

Categoria: Criacional

Objetivo: Definir uma interface para criar objetos, mas deixar as subclasses decidirem qual classe instanciar.

Onde foi aplicado?

Arquivo: app/factories/ProductFactory.php
Uso: Criação de diferentes tipos de produtos

Tipos de Produtos Suportados

Tipo Desconto Garantia Prioridade
Novo 0% Sim Alta
Usado 10% Não Média
Promocional 20% Sim Máxima
Vintage 0% Não Alta

Implementação

abstract class ProductFactory { public static function createProduct(array $data): Product { $condicao = $data['condicao'] ?? 'usado'; switch (strtolower($condicao)) { case 'novo': return self::createNewProduct($data); case 'usado': return self::createUsedProduct($data); case 'promocional': return self::createPromotionalProduct($data); case 'vintage': return self::createVintageProduct($data); } } private static function createNewProduct($data): Product { $product = new Product(); $product->setData($data); $product->setDesconto(0); $product->setGarantia(true); return $product; } }
✅ Benefício: Adicionar novos tipos de produtos é simples, sem modificar código existente.
