4. Padrões GoF - Observer

👁️ Observer Pattern

Categoria: Comportamental

Objetivo: Definir uma dependência um-para-muitos entre objetos, de modo que quando um objeto muda de estado, todos os seus dependentes são notificados.

Onde foi aplicado?

Arquivos:
- app/observers/Observer.php (interface)
- app/observers/Subject.php (interface)
- app/observers/ProductPublisher.php (subject)
- app/observers/NotificationObserver.php (observer)

Sistema de Notificações

O Observer foi implementado para desacoplar o sistema de notificações. Quando um evento ocorre (novo produto, promoção), os observadores são automaticamente notificados.

Fluxo do Observer

┌──────────────────────┐
│  ProductPublisher    │ (Subject)
│  - attach()          │
│  - detach()          │
│  - notify()          │
└──────────┬───────────┘
           │
           │ notify("new_product", data)
           │
           ▼
┌──────────────────────────────────┐
│  NotificationObserver            │
│  - update(eventType, data)       │
│  - handleNewProduct()            │
│  - handlePromotion()             │
│  - createNotificationForAllUsers()│
└──────────────────────────────────┘
           │
           ▼
    [Banco de Dados]
    Tabela: notificacoes

Eventos Suportados

  • new_product: Quando um novo produto é adicionado
  • promotion: Quando uma promoção é criada
  • store_update: Quando um brechó é atualizado
  • product_promotion: Quando um produto entra em promoção

Implementação

// Observer Interface interface Observer { public function update(string $eventType, array $data): void; } // Subject Interface interface Subject { public function attach(Observer $observer): void; public function detach(Observer $observer): void; public function notify(string $eventType, array $data): void; } // Implementação Concreta class NotificationObserver implements Observer { public function update(string $eventType, array $data): void { switch ($eventType) { case 'new_product': $this->handleNewProduct($data); break; case 'promotion': $this->handlePromotion($data); break; } } private function handleNewProduct(array $data): void { $titulo = "Novo produto disponível!"; $mensagem = "O produto '{$data['product_name']}' foi adicionado."; $this->createNotificationForAllUsers($titulo, $mensagem); } }
✅ Benefício: Sistema de notificações totalmente desacoplado. Novos tipos de observadores podem ser adicionados sem modificar o código existente.

4. Padrões GoF - Strategy + Decorator

🎯 Strategy Pattern

Categoria: Comportamental

Objetivo: Definir uma família de algoritmos, encapsular cada um deles e torná-los intercambiáveis.

🎨 Decorator Pattern

Categoria: Estrutural

Objetivo: Anexar responsabilidades adicionais a um objeto dinamicamente.

Onde foi aplicado?

Arquivos:
- app/search/SearchStrategy.php
- app/search/BuscarProdutosStrategy.php
- app/search/ProdutoSearchBase.php
- app/search/decorators/ (8 decorators)

Sistema de Busca Flexível

A combinação Strategy + Decorator cria um sistema de busca altamente flexível onde:

  • Strategy: Define o contexto de busca (produtos, lojas, etc.)
  • Decorator: Aplica filtros dinamicamente (categoria, preço, cor, etc.)

Decorators Disponíveis

Decorator Função
FiltroCategoriaDecorator Filtra por categoria
FiltroPrecoMinDecorator Filtra por preço mínimo
FiltroPrecoMaxDecorator Filtra por preço máximo
FiltroMarcaDecorator Filtra por marca
FiltroCorDecorator Filtra por cor
FiltroTamanhoDecorator Filtra por tamanho
FiltroCondicaoDecorator Filtra por condição
FiltroTextoDecorator Busca textual

Strategy + Decorator - Implementação

Fluxo de Busca

1. ProductController recebe filtros do usuário
   ↓
2. BuscarProdutosStrategy é instanciada
   ↓
3. Strategy aplica Decorators dinamicamente:
   - ProdutoSearchBase (busca base)
   - + FiltroCategoriaDecorator (se categoria informada)
   - + FiltroPrecoMaxDecorator (se preço máximo informado)
   - + FiltroCorDecorator (se cor informada)
   ↓
4. Cada Decorator modifica o SQL:
   - Adiciona cláusulas WHERE
   - Adiciona parâmetros
   ↓
5. ProductRepository executa SQL final
   ↓
6. Retorna resultados filtrados

Código da Strategy

class BuscarProdutosStrategy implements SearchStrategy { private $repo; private array $filters; public function search(): array { // 1. Busca base $search = new ProdutoSearchBase(); // 2. Aplica decorators dinamicamente if (isset($this->filters['categoria'])) { $search = new FiltroCategoriaDecorator( $search, $this->filters['categoria'] ); } if (isset($this->filters['preco_max'])) { $search = new FiltroPrecoMaxDecorator( $search, $this->filters['preco_max'] ); } // 3. Executa no repository return $this->repo->executarBusca($search); } }

Código do Decorator

class FiltroCategoriaDecorator implements ProdutoSearchInterface { private $busca; private $categoria; public function __construct($busca, $categoria) { $this->busca = $busca; $this->categoria = $categoria; } public function getSQL(): string { return $this->busca->getSQL() . " AND c.slug = :categoria"; } public function getParams(): array { $params = $this->busca->getParams(); $params[':categoria'] = $this->categoria; return $params; } }
✅ Benefício: Filtros são aplicados a nível de SQL (eficiente), podem ser combinados dinamicamente, e novos filtros são fáceis de adicionar.

5. Integração dos Padrões

Como os Padrões Trabalham Juntos

Fluxo Completo de uma Busca de Produtos

┌─────────────────────────────────────────────────────┐
│ 1. USUÁRIO faz busca por "vestido vermelho < R$100" │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 2. ProductController recebe requisição             │
│    - Extrai filtros: cor=vermelho, preco_max=100   │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 3. Singleton: DatabaseConnection::getInstance()    │
│    - Retorna conexão PDO única                     │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 4. Repository: new ProductRepository($db)          │
│    - Recebe conexão Singleton                      │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 5. Strategy: new BuscarProdutosStrategy()          │
│    - Aplica Decorators:                            │
│      * FiltroCorDecorator("vermelho")              │
│      * FiltroPrecoMaxDecorator(100)                │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 6. Repository executa SQL composto                 │
│    SELECT * FROM produtos                          │
│    WHERE cor = 'vermelho' AND preco <= 100         │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 7. Factory: ProductFactory::createFromDatabase()   │
│    - Cria objetos Product tipados                  │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 8. Observer: Se novo produto, notifica usuários    │
│    - ProductPublisher->notify("new_product")       │
│    - NotificationObserver cria notificações        │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ 9. View renderiza resultados para o usuário        │
└─────────────────────────────────────────────────────┘

Relações Entre Padrões

Padrão 1 Padrão 2 Relação
Singleton Repository Conexão única injetada nos repositórios
Factory Observer Produtos criados podem disparar eventos
Strategy Decorator Strategy usa Decorators para compor filtros
Repository Strategy Repository executa buscas compostas
